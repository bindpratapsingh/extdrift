  1. BASE PAPER  (the professor's primary request)
===============================================================================

  CHANGE
    Replaced the named base paper.
      OLD: S. Singh et al., "A Study on Malicious Browser Extensions in 2025,"
           arXiv, 2025.
      NEW: D. Bui, B. Tang, K. G. Shin, "Detection of Inconsistencies in
           Privacy Practices of Browser Extensions (ExtPrivA),"
           IEEE Symposium on Security & Privacy (S&P), 2023.

  WHY
    - The Singh paper is an arXiv PREPRINT — not peer-reviewed and not formally
      published — which is exactly why it does not qualify as a base paper.
    - IEEE S&P is a top-tier, IEEE-published security venue, satisfying the
      "IEEE published" requirement with a highly credible source.
    - It is also the closest methodological match available: ExtPrivA emulates
      user interaction to trigger extension functionality and analyses outbound
      network requests to detect data leakage — structurally the same as our
      approach. We can therefore frame our work cleanly as an extension of it
      from single-version analysis to the UPDATE / version-diff setting.
    - Singh, JavaSith, and "Did I Vet You Before?" are kept as supporting /
      motivation references (clearly marked as preprints), not as the base paper.

  3. MULTI-BROWSER COVERAGE  (the professor's meeting note: "for multiple browsers")
===============================================================================

  CHANGE
    Added explicit multi-browser / cross-engine scope (new dedicated section in
    the detailed proposal; reflected in the official form's problem statement):
      - Chromium family (Chrome, Edge, Brave) — PRIMARY target.
      - Firefox — SECOND engine, for genuine cross-engine coverage.
      - Safari — explicitly OUT OF SCOPE.

  WHY
    - Directly addresses the advisor's note.
    - Chrome, Edge, and Brave share the Manifest V3 .crx format and the
      chrome.* API, so one instrumentation back-end covers all of them with
      little extra work — and this is the family hit by the Cyberhaven attack.
    - Firefox uses a different package (.xpi), API (browser.*), and engine
      (Gecko); supporting it is more work but yields real cross-engine value
      and exposes behaviour an extension reveals only under one engine.
    - Safari's App-Extension model is macOS-only and structurally different —
      not worth the cost, so it is excluded deliberately rather than by omission.

  4. DATA-PLAN CORRECTION  (feasibility)
===============================================================================

  CHANGE 4a — Removed CRXcavator as a data source.

  WHY
    - CRXcavator was sunset by Cisco/Duo in 2023 and no longer exists, so it
      cannot supply data. Citing a dead tool would undermine feasibility.

  CHANGE 4b — Made the training strategy explicit and honest.
    Train PRIMARILY on a synthetic weaponisation corpus (clean extensions with
    known malicious behaviours injected to create labelled version pairs);
    RESERVE confirmed real 2024-25 incidents as a held-out validation set.

  WHY
    - Confirmed malicious UPDATE PAIRS (version N vs N+1) are very scarce in the
      wild — only a handful of well-documented campaigns. A classifier trained
      only on those would be data-starved and easy to over-claim.
    - Synthetic-train / real-validate is the honest, defensible framing and
      pre-empts the obvious examiner question about dataset size.


===============================================================================
  5. TECHNICAL MODERNIZATIONS
===============================================================================

  CHANGE 5a — Manifest V3 made the explicit target.
  WHY
    - Chrome has moved to MV3 (service workers, declarativeNetRequest, no remote
      code), and the Cyberhaven attack itself was MV3. Naming MV3 shows the
      project targets the current platform and clarifies how API calls are hooked.

  CHANGE 5b — Replaced "Alexa sites" with the Tranco list.
  WHY
    - Alexa rankings were discontinued in 2022. Tranco is the current academic
      standard for top-sites rankings.

  CHANGE 5c — Added record/replay determinism.
  WHY
    - Browsing real sites twice never yields identical network traffic (ads,
      nonces, timestamps, A/B content). Diffing raw traces would produce false
      positives. Driving both versions against identical, replayed page content
      isolates the extension as the only variable — this is also a methodological
      contribution in its own right.

  CHANGE 5d — Added a transparent weighted-rule baseline alongside the
              Random Forest.
  WHY
    - Strengthens the "explainable output" goal, gives a sanity-check against the
      learned model, and is robust when real malicious data is thin. Agreement
      between the two scorers is itself reported as a confidence signal.
